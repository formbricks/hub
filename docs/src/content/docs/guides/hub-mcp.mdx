The `@formbricks/hub-mcp` package lets MCP-capable AI clients work with Formbricks Hub through the generated Hub TypeScript client. AI clients can launch it as a local stdio MCP server, while release smoke tests can start it over HTTP. In both cases it points at either a local Hub instance or a self-hosted production deployment.

## What You Need

- A running Hub API, such as `http://localhost:8080` from the [Quick Start](/quickstart) or a deployed HTTPS URL.
- The Hub API key configured as `API_KEY` on the Hub server.
- Node.js and `npx` on the machine where your AI client starts MCP servers.
- An AI client that supports local stdio MCP servers.
- For local Code Mode, Deno installed on the same machine as the MCP server.

<Callout variant="note">
  Treat MCP access like direct API access. The MCP package receives an API key
  with the same permissions as `Authorization: Bearer &lt;API_KEY&gt;`, so keep
  it out of committed config files and use environment-specific keys.
</Callout>

## Choose Code Execution Mode

The generated MCP server exposes an `execute` tool. By default, generated MCP
packages may run that tool through Stainless-hosted Code Mode. For self-hosted
Hub deployments, prefer local Code Mode so the generated code runs on the same
machine as the MCP server and calls your Hub API directly.

Local Code Mode:

- keeps execution local to the MCP server machine
- avoids hosted sandbox network allowlist issues for self-hosted Hub domains
- requires Deno on the machine that runs the MCP server
- still treats the Hub API key like a direct Hub API credential

<Callout variant="note">
  The examples below require an MCP package release that supports
  <code>FORMBRICKS_HUB_BASE_URL</code> and <code>--code-execution-mode</code>.
  If you are validating changes before that package is published, use a local
  MCP build as shown in the smoke test section.
</Callout>

## Configure the MCP Server

Add a stdio MCP server entry to your AI client's MCP configuration:

```json
{
  "mcpServers": {
    "formbricks-hub": {
      "command": "npx",
      "args": [
        "-y",
        "@formbricks/hub-mcp@latest",
        "--code-execution-mode",
        "local",
        "--docs-search-mode",
        "local"
      ],
      "env": {
        "HUB_API_KEY": "your_hub_api_key",
        "FORMBRICKS_HUB_BASE_URL": "https://hub.example.com"
      }
    }
  }
}
```

For local Docker Compose from the [Quick Start](/quickstart), use:

```json
{
  "mcpServers": {
    "formbricks-hub-local": {
      "command": "npx",
      "args": [
        "-y",
        "@formbricks/hub-mcp@latest",
        "--code-execution-mode",
        "local",
        "--docs-search-mode",
        "local"
      ],
      "env": {
        "HUB_API_KEY": "your_secure_api_key_here",
        "FORMBRICKS_HUB_BASE_URL": "http://localhost:8080"
      }
    }
  }
}
```

`HUB_API_KEY` is the key the MCP package sends to Hub. It should match the `API_KEY` value used by the Hub API.

`FORMBRICKS_HUB_BASE_URL` is the public base URL for the Hub API. Use the API root, not a `/v1` URL. Examples:

| Deployment style          | Base URL                  |
| ------------------------- | ------------------------- |
| Local Docker Compose      | `http://localhost:8080`   |
| Dedicated domain          | `https://hub.example.com` |
| Reverse-proxy path prefix | `https://example.com/hub` |

The Hub source repository's smoke test accepts `HUB_BASE_URL` as a legacy input
alias, but MCP client configurations should use `FORMBRICKS_HUB_BASE_URL`.

<Callout variant="note">
  Avoid running one shared remote MCP server with a single global Hub API key for
  multiple users. For shared MCP infrastructure, prefer per-request
  authorization headers and revocable, environment-specific Hub keys. Local
  stdio MCP keeps each user's key on the machine where their AI client runs.
</Callout>

## Use the MCP Tool

The MCP package exposes an `execute` tool that runs JavaScript against the Hub client. In most AI clients, you can ask the assistant to create, list, update, delete, or search feedback records and let it call the MCP tool.

A typical workflow looks like this:

```js
async function run(client) {
  let created = null;

  try {
    created = await client.feedbackRecords.create({
      tenant_id: "org-123",
      submission_id: "mcp-demo-001",
      source_type: "survey",
      source_id: "mcp-demo",
      source_name: "MCP Demo",
      field_id: "q1",
      field_label: "How satisfied are you?",
      field_type: "rating",
      value_number: 5,
      user_id: "mcp-demo-user",
      language: "en",
    });

    const listed = await client.feedbackRecords.list({
      tenant_id: "org-123",
      submission_id: "mcp-demo-001",
      limit: 10,
    });

    return {
      createdID: created.id,
      listedCount: listed.data.length,
    };
  } finally {
    if (created?.id) {
      await client.feedbackRecords.delete(created.id);
    }
  }
}
```

Useful prompts for an MCP-enabled AI client:

- "List the latest 10 feedback records for tenant `org-123`."
- "Create a test text feedback record for tenant `org-123`, then delete it."
- "Find feedback records for submission `subm-001` and summarize the fields."

## Self-Hosted Production Setup

For production deployments, set `PUBLIC_BASE_URL` on the Hub API process when Hub is exposed through ingress, TLS termination, a reverse proxy, or a path prefix:

```bash
PUBLIC_BASE_URL=https://hub.example.com
```

or:

```bash
PUBLIC_BASE_URL=https://example.com/hub
```

Hub uses `PUBLIC_BASE_URL` when serving runtime OpenAPI specs at:

- `GET /openapi.yaml`
- `GET /openapi.json`

Those endpoints are public by design, like `GET /health`. Keep `/v1/*` protected with `Authorization: Bearer <API_KEY>`.

<Callout variant="note">
  `PUBLIC_BASE_URL` belongs to the Hub API deployment. `FORMBRICKS_HUB_BASE_URL`
  belongs to the MCP client process. In many deployments they have the same URL,
  but they are read by different processes.
</Callout>

## Run the MCP Smoke Test

In a checkout of the Hub source repository, you can run the live MCP package smoke test against a deployed Hub instance:

```bash
HUB_API_KEY=your_hub_api_key \
FORMBRICKS_HUB_BASE_URL=https://hub.example.com \
HUB_MCP_PACKAGE=@formbricks/hub-mcp@latest \
make mcp-smoke
```

The smoke test starts the configured MCP server over local HTTP, checks for the `execute` tool, creates a feedback record, lists it, and deletes it again. `HUB_API_KEY` is sent to the local MCP HTTP server as an authorization header; the key should match the Hub server's `API_KEY`.

To test a specific package version or preview build, change `HUB_MCP_PACKAGE`:

```bash
HUB_API_KEY=your_hub_api_key \
FORMBRICKS_HUB_BASE_URL=https://hub.example.com \
HUB_MCP_PACKAGE=@formbricks/hub-mcp@1.2.3 \
make mcp-smoke
```

To test a local MCP build instead of a published package, use `HUB_MCP_COMMAND`. `HUB_MCP_COMMAND` takes precedence over `HUB_MCP_PACKAGE`; `HUB_MCP_ARGS` is split into command arguments.

```bash
HUB_API_KEY=your_hub_api_key \
FORMBRICKS_HUB_BASE_URL=https://hub.example.com \
HUB_MCP_COMMAND=node \
HUB_MCP_ARGS="/workspace/hub-typescript/packages/mcp-server/dist/index.js --code-execution-mode local --docs-search-mode local" \
make mcp-smoke
```

The `make mcp-smoke` target sources `.env` from the Hub repository before
running the test. If `.env` contains a different `FORMBRICKS_HUB_BASE_URL`,
`HUB_BASE_URL`, or `HUB_API_KEY`, update `.env` or run the underlying `go test`
command with explicit environment values.

## Troubleshooting

### MCP Requests Return 401

Check that `HUB_API_KEY` in the MCP configuration exactly matches the Hub server's `API_KEY`.

### The Client Cannot Reach Hub

Make sure `FORMBRICKS_HUB_BASE_URL` is reachable from the machine running the AI client. For local Docker Compose on the same machine, `http://localhost:8080` usually works. If the AI client runs inside another container, use the hostname that is reachable from that container.

If hosted Code Mode returns a message such as `Network access to <host>:443 is
blocked`, switch to local Code Mode or regenerate/release the MCP package from
an OpenAPI spec whose `servers` array explicitly includes that host.

### MCP Local Code Mode Cannot Start

Install Deno and make sure it is available on `PATH` for the process that starts
the MCP server:

```bash
deno --version
```

Local Code Mode uses Deno to run the AI-generated SDK code with constrained
network access to the configured Hub base URL.

### Hub Rejects `user_id`

If the smoke test or MCP demo returns `json: unknown field "user_id"`, the Hub
deployment is older than the current API contract. Deploy a Hub version that
includes the `user_identifier` to `user_id` migration and regenerated OpenAPI
contract, then rerun the smoke test.

### Runtime OpenAPI URLs Show the Wrong Host

Set `PUBLIC_BASE_URL` on the Hub API deployment and restart the API. Use an absolute `http` or `https` URL without query strings, fragments, or credentials.

### `npx` Starts the Wrong Package Version

Pin the package in your MCP config:

```json
"args": ["-y", "@formbricks/hub-mcp@1.2.3"]
```

For release validation, use the same package spec in `HUB_MCP_PACKAGE` when running `make mcp-smoke`.

Before publishing docs that use `@latest`, confirm the npm package has the
expected release:

```bash
npm view @formbricks/hub-mcp version
```

### `make mcp-smoke` Requires a Package or Command

Set either `HUB_MCP_PACKAGE` for a published package or `HUB_MCP_COMMAND` for a local MCP server build. The smoke test intentionally requires one of these so it validates the exact MCP build under review.
