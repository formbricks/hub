# Docs site guidelines

The repository-wide conventions in `../AGENTS.md` apply here too — including the
commit and pull-request rules. This file covers only what is specific to `docs/`.

This is the only non-Go part of the Hub repo: an Astro + Starlight site, with its
own `package.json` and `node_modules`.

## Structure
- `src/content/docs/`: pages (`.md`/`.mdx`). Landing page is `index.mdx`.
- `src/content/docs/core-concepts/`, `guides/`, `reference/`: the three prose sections.
- `src/content.config.ts`: Starlight content collection/schema wiring.
- `astro.config.ts`: sidebar topics, the OpenAPI reference wiring, head/theme config.
- `public/`: static assets served as-is (favicons, web manifest).
- `src/assets/`: images imported from content.
- `theme.css`: brand tokens (`--fb-*`) and overrides on Starlight's own (`--sl-*`).

## Commands
Run from this directory:
- `pnpm install`, `pnpm dev` (http://localhost:4321), `pnpm build`, `pnpm preview`
- `pnpm check`: `astro check` — types and content-collection schemas
- `pnpm format`: Prettier

## The API reference is generated
It comes from `../openapi.yaml` via `starlight-openapi`, served under `/api/`. It is
never hand-written: to change it, change the spec. Because the docs build parses the
spec, an invalid spec fails this build as well as `code-quality.yml`'s Spectral lint.

**The build takes no secrets and makes no network calls.** That is the point of
ENG-2369 — the previous site fetched its API reference from Stainless at build time
using a `STAINLESS_API_KEY`. If the build ever needs a credential again, something has
regressed.

## Writing
- `kebab-case` filenames (e.g. `quickstart.mdx`).
- Keep frontmatter minimal and explicit (`title`, `description`).
- Use Starlight components from `@astrojs/starlight/components` — `<Aside>`, `<Card>`,
  `<LinkButton>`, `<Tabs>`. Do not reintroduce a bespoke component library.
- Adding a page means adding it to the sidebar in `astro.config.ts`; there is no
  autogenerated section, so an unlisted page is unreachable.
- 2-space indentation; for TypeScript config, ES modules, double quotes, semicolons.

## Validating a change
1. `pnpm check` and `pnpm build` — both must pass.
2. `pnpm preview` and review the changed pages.
3. For anything touching `theme.css` or the landing page, check light *and* dark mode.
